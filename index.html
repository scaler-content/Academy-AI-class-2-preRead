Prompt Engineering, and the Prompt That Runs Your App

Learn why instructions change product quality and preview the prompt techniques that turn a generic model response into a useful website summary.

About 35–40 minutesRead before classQuick checks included

1. Welcome

Class 1 established that a model can answer from a prompt. Class 2 focuses on what you tell it to do and turns the instructions into the website summariser's product behaviour.

What to focus on
Understand the mental model first; you do not need to memorise every detail before class.

2. The prompt is part of the product

“Summarise this” leaves the model to guess the audience, length, format and what matters. A stronger prompt specifies those choices so the output is more useful and consistent.

3. RCTFC: five parts of a complete prompt

Use Role, Context, Task, Format and Constraints. Role describes the perspective; Context explains the situation and audience; Task says what to do; Format describes the output shape; Constraints define limits and exclusions. A prompt can be short while still complete.

4. Role and examples

Role prompting can guide tone but does not guarantee correctness. Zero-shot prompting gives instructions without examples. Few-shot prompting includes examples of the desired input/output pattern, which can help when consistency matters.

5. Structured outputs

If another program needs the response, prose may be difficult to parse. Asking for JSON makes fields explicit, but does not remove the need to validate the response for missing fields, malformed syntax or unexpected values.

6. Reasoning, self-critique and prompt chains

Self-critique asks the model to check its work against criteria, but the model can still miss mistakes. Prompt chaining splits a complex job into smaller calls, such as extracting facts before summarising. Extra calls add latency, cost and failure points.
